# LRU cache

## Задача
Реализуйте потокобезопасный LRU-кэш (Least Recently Used) с ограниченной ёмкостью. При переполнении кэша должен удаляться элемент, который не использовался дольше всех.

## API

- `NewLRUCache(capacity int) *Cache` — паникует, если `capacity <= 0`.
- `Get(key int) (int, error)` — возвращает значение и помечает ключ как самый недавно использованный; `ErrNotFound`, если ключа нет.
- `Put(key, value int)` — вставляет новый ключ или обновляет значение существующего и помечает его как самый недавно использованный; при превышении ёмкости вытесняет наименее недавно использованный элемент.
- `Peek(key int) (int, error)` — как `Get`, но не меняет порядок использования.
- `Contains(key int) bool` — проверяет наличие ключа, не меняя порядок использования.
- `Delete(key int) error` — удаляет ключ; `ErrNotFound`, если ключа нет.
- `Len() int` / `Cap() int` — текущее количество элементов и ёмкость кэша.
- `Keys() []int` — ключи от самого недавно использованного к самому старому.
- `Clear()` — полностью очищает кэш.

## Реализация

- Двусвязный список с sentinel-узлами `head`/`tail` + `map[key]*node`: у каждого реального узла всегда есть непустые `prev`/`next`, поэтому вставка, удаление и перемещение в начало списка не требуют веток на `nil` и выполняются за O(1).
- Все операции, включая `Get`, защищены одним `sync.Mutex`: `Get` тоже меняет порядок использования, то есть является записью, а не чтением, поэтому `RWMutex` здесь не даёт выгоды.
